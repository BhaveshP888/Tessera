Architecture · High-Level Design

Tessera — a privacy-first
bookmark manager

A local-first, end-to-end encrypted bookmark manager with a typed extension system and zero AI. Bookmarks live on your device in a SQLite database; an optional cloud relay syncs them under a key only you hold. No telemetry, no recommendations, no embeddings — just fast, structured retrieval and a capable plugin model for the rest.

P01
No AI, ever
Deterministic by design. Search is SQLite FTS5 + trigram fuzzy; tagging and folders are user-driven. No embeddings, no vector store, no model inference on device or server.
P02
Strict privacy
Local-first storage, E2E-encrypted sync, zero-knowledge relay. No analytics, no third-party CDNs in the app shell, strict CSP, and a self-hosted reader proxy that strips identifiers.
P03
Extensible
A typed TypeScript SDK with capability-scoped permissions. Extensions run in a sandboxed iframe / Web Worker with no direct DOM access, communicating over typed postMessage.

Privacy & Security Model

Zero-knowledge by construction

Key hierarchy
// Derived once at setup, stored in OS keychain masterKey = randomBytes(32) // never leaves device unencrypted // Per-record encryption, randomised nonce recordKey = HKDF(masterKey, "record:" + id) ciphertext = XChaCha20Poly1305(recordKey, nonce, plaintext) // Device keypair for sync auth + envelope {pub, priv} = X25519.generate() sessionKey = X25519.derive(priv, serverPub)
Threat model. A compromised server sees only ciphertext, device public keys, and sync cursors. Linking bookmarks across devices is impossible without the master key. The reader proxy is the only component that ever fetches a remote URL — and it is opt-in, stateless, and strips identifying headers.
Guarantees
  • Local-first — app is fully functional offline; sync is additive.
  • E2E encryption — every record encrypted on device before any network call.
  • No telemetry — zero analytics SDKs, no crash reporters that phone home.
  • Strict CSP — script-src 'self' + hashes; no unsafe-inline, no remote scripts.
  • No third-party CDNs — fonts and assets are bundled or self-hosted.
  • Passkey auth — WebAuthn only; no password column exists in the schema.
  • Reader proxy — opt-in, rotates egress IP, discards cookies and referer.
  • Audit log — every sync, device add/remove, and extension install is logged locally, inspectable by the user.
  • Export & wipe — full plaintext export and one-click server-side data destruction.
Extension System

Sandboxed, typed, capability-scoped

Extension manifest
export default defineExtension({ id: "pinboard-import", name: "Pinboard Importer", version: "1.0.0", author: "tessera.community", permissions: [ "bookmarks.write", "tags.write", ], ui: { panel: "./panel.html", // iframe sandbox commands: ["import-from-url"], }, hooks: { onCommand: handleImport, }, });
Runtime model
  • UI panel — rendered in a sandboxed iframe with allow-scripts only; no same-origin, no access to the app DOM.
  • Logic — runs in a Web Worker; receives typed RPC over postMessage.
  • Capability checks — every API call is gated by the manifest's declared permissions; undeclared access throws at the boundary.
  • Network — network.fetch permission routes through the reader proxy, never the user's session.
  • Storage — extensions get a namespaced KV store; they cannot read the core bookmark DB.
  • Signing — manifests are signed by an author key; the registry verifies signatures on install.
  • Revocation — one-click disable per extension; an extension crash never takes down the host.

Sync & Data Flow

How a bookmark travels

Save & sync pipeline
01
Capture
Extension or web app saves URL + title + selection. Stored locally first.
→
02
Enrich
Metadata fetched client-side, or via opt-in reader proxy. No remote tracking.
03
Index
FTS5 + trigram index updated locally. Full-text search ready instantly.
→
04
Encrypt
Record sealed with derived key; nonce randomised. Server sees ciphertext only.
→
05
Push
Encrypted delta + vector clock sent to relay over HTTPS. Cursor advanced.
→
06
Pull
Other devices fetch deltas, decrypt, reconcile via per-field LWW + tombstones.
Conflict resolution. Each field carries a (device_id, lamport_ts) vector clock. On merge, the highest timestamp wins per field; deletes are tombstones with the same clock discipline. No CRDT complexity — predictable, inspectable, and reversible via the local audit log.
Monorepo Structure

One TypeScript tree, three runtimes

tessera/ ├── packages/ │ ├── core/ shared local sync core │ │ ├── db/ drizzle schema + migrations │ │ ├── crypto/ key derivation, sealing │ │ ├── sync/ vector clocks, LWW, tombstones │ │ └── search/ FTS5 + trigram engine │ ├── sdk/ extension SDK + types │ └── schemas/ zod schemas, shared API types ├── apps/ │ ├── web/ React + Vite SPA │ ├── extension/ MV3 browser extension │ └── desktop/ Tauri shell (optional) ├── server/ Fastify API + relay │ ├── auth/ WebAuthn / passkey │ ├── relay/ encrypted blob store │ └── registry/ extension manifest host ├── extensions/ first-party reference extensions ├── pnpm-workspace.yaml └── turbo.json
Why a monorepo
  • packages/schemas — one Zod source for client, server, and extension types.
  • packages/core — identical sync + crypto logic in every runtime.
  • turbo — cached, parallel builds across the graph.
  • No code duplication between the extension, web app, and server.
  • Schema migrations ship once and apply to all runtimes.
Shared schema, one migration path. The Drizzle schema in packages/core/db is the single source of truth. The same migration runs against WASM SQLite in the browser, native SQLite on desktop, and (for relay metadata) Postgres on the server.

Key Decisions

Where the hard calls landed

Q · Search without AI?
SQLite FTS5 + trigram for title, URL, notes, and tags.
No embeddings means no model, no vector store, no inference cost, and no opaque ranking. Search is exact, fast, and inspectable — matches the "no AI" principle directly.
Q · Sync without a CRDT?
Vector clocks + per-field LWW + tombstones.
Bookmarks are low-write, low-conflict data. A CRDT adds complexity for little gain. LWW is predictable, reversible via the audit log, and trivial to reason about.
Q · Why SQLite everywhere?
One schema, one migration path, three runtimes.
WASM SQLite runs in the browser and extension; native SQLite runs in desktop and server. Drizzle abstracts the difference. No IndexedDB juggling, no separate server data model.
Q · Extension sandbox model?
iframe for UI, Web Worker for logic, typed postMessage RPC.
No direct DOM access means an extension cannot read the user's bookmarks unless granted bookmarks.read. Capability checks at the boundary keep the host safe even if an extension is malicious.
Q · Auth approach?
WebAuthn / passkeys only. No passwords.
Passwords are a liability. Passkeys are phishing-resistant, device-bound, and require no server-side secret storage. The schema has no password column by construction.
Q · Link previews & privacy?
Client-side fetch first; opt-in stateless reader proxy as fallback.
Fetching a URL leaks your reading list to that site. Client-side fetch uses the user's session; the proxy is the privacy-preserving fallback that strips cookies, referer, and rotates egress IPs.
Deployment

Self-host primary, cloud optional

Self-hosted (default)
  • Single Docker image: Fastify API + static web bundle + SQLite relay.
  • docker run tessera/server — one port, one volume, done.
  • Desktop app bundles its own server for fully offline use.
  • Browser extension talks to localhost or a user-chosen domain.
  • No cloud account required; sync can be LAN-only or disabled.
Optional cloud sync
  • Managed relay at sync.tessera.app — still zero-knowledge.
  • Only encrypted blobs + cursors are stored; the server has no decryption key.
  • Account = passkey only; no email required if self-hosting.
  • Object store for encrypted snapshots / exports, keyed by content hash.
  • Self-hosted instances can opt into the same relay or federate peer-to-peer.
Local-first invariant. Every feature works offline. The cloud relay only ever syncs data the user already has on their device; it is never a source of truth. If the relay disappears, the user's tessera.db is the complete, usable library.
